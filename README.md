# Complio

Complio screens a German small or medium-sized enterprise against its applicable
regulatory obligations and produces a plain-language compliance report. It combines a
deterministic rule engine, which decides applicability and statutory thresholds in
code rather than delegating that to a language model, with a Retrieval-Augmented
Generation pipeline over German and EU legal text, and a three-step validation chain
that checks every finding's citation, evidence quote, and semantic entailment before
it reaches a report.

This repository is the prototype built for the accompanying bachelor thesis
("Complio: An Autonomous AI Agent for Regulatory Compliance Screening at German
SMEs"). The thesis documents the design, the evaluation, and the limitations in
detail; this README covers what's here and how to run it.

## What it covers

Fourteen German and EU regulations, each with its own applicability logic, statutory
thresholds, and curated knowledge base:

GDPR/DSGVO, BDSG, LkSG, EDL-G/EnEfG, CSRD, EU Data Act, NIS2, HinSchG, ArbSchG, AGG,
MiLoG, TTDSG/TDDDG, GwG, EU AI Act.

## Architecture

- **Rule engine** (`backend/services/threshold_engine.py`) — applicability and
  statutory thresholds (employee count, turnover, sector) are evaluated in code, not
  inferred by an LLM.
- **RAG pipeline** (`backend/rag/`) — regulation texts are chunked at article/section
  level, embedded with a multilingual model, and indexed in ChromaDB (with a pgvector
  migration path in progress). Retrieval is hybrid: dense similarity, BM25, and a
  statute-citation bonus, tuned per collection.
- **Agent** (`backend/agent/`) — orchestrates the gap analysis: retrieves grounding
  evidence, drafts findings, and validates each one (citation match, evidence quote
  check, semantic entailment) before it's allowed into a report.
- **Report generation** (`backend/services/pdf_generator.py`) — renders a
  plain-language PDF via a headless browser with outbound network access blocked
  during rendering, plus a fuller JSON output for technical consumers.
- **Frontend** (`frontend/`) — Next.js app for uploading company documents, running
  an analysis, and reviewing the report.

## Stack

- Backend: FastAPI, SQLAlchemy (async) + PostgreSQL/Supabase, ChromaDB, Celery +
  Redis (optional — falls back to asyncio without it), Playwright (PDF rendering)
- Frontend: Next.js 14, React 18, Tailwind CSS, Supabase auth
- LLM: Anthropic Claude via the `anthropic` SDK

## Running it locally

### Backend

```bash
cd backend
pip install -r ../requirements.txt
cp ../.env.example .env   # fill in the required values, see comments in the file
python setup_data.py      # fetch and ingest regulation source texts
uvicorn main:app --reload
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

### Docker Compose

```bash
docker compose up --build
```

Brings up ChromaDB, the backend API, the Celery worker, and the frontend together.
See `.env.example` for the full list of environment variables; only the LLM and
database ones are required to get a working pipeline.

## Testing

```bash
cd backend
pytest
python scripts/eval_retrieval.py            # retrieval accuracy against a hand-labelled eval set
python scripts/eval_obligation_coverage.py  # obligation-level coverage check
```

CI (`.github/workflows/ci.yml`) runs the test suite and linting on every push;
CodeQL (`.github/workflows/codeql.yml`) runs static security analysis.

## Disclaimer

Complio produces a preliminary compliance screening, not legal advice. Reports
generated by this tool are not a substitute for consultation with a licensed
Rechtsanwalt.
